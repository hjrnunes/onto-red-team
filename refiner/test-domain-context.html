Domain Context Report

Reading Guide

What is domain context? Domain context provides the ontological variation dimensions for each risk-policy mapping. It defines the axes along which red-team prompts can be varied (agent types, data types, processes, etc.) and enumerates concrete values from the knowledge graph for each axis.

What are axes? Each axis is a CCO or domain ontology class that represents one dimension of prompt variation. For example, "Person" might be an axis, allowing prompts to vary across different types of people (executives, analysts, customers). Axes are tagged with BFO categories (Object, Process, Quality, etc.) and semantic roles (agent, instrument, object) that determine how they're used in prompt generation.

What are enumerations? Enumerations are the concrete values for each axis, drawn from the ontology. For a "Person" axis, enumerations might include "Software Engineer", "Medical Doctor", "Financial Analyst". Each enumeration has a relevance score (high/medium/low) assigned by the LLM - high-relevance values are sampled 3x more often during prompt generation.

How are they discovered? Axes and enumerations come from multiple sources: structural (ontology hierarchy and axioms), search (semantic similarity), and generated (LLM-created with policy context when ontology coverage is insufficient). The provenance field tracks the discovery method for each enumeration.

How to use this report: Expand each policy concept to see its risk groundings. Each grounding shows the variation axes for one risk. Review the axes to understand what dimensions are available, and check enumerations to see if the ontology provides sufficient coverage for your domain.
